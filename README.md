# gator

`gator` is a command-line RSS feed aggregator. You add RSS feeds, follow the ones you like, and leave the aggregator running in the background to collect new posts into a Postgres database. You can then browse the latest posts from your terminal.

Several users can share one database. Each user follows their own feeds and sees their own posts.

## Requirements

- **Go 1.27 or newer.** You need it only to build and install `gator`. The installed `gator` binary runs without Go.
- **PostgreSQL 13 or newer.** All of your users, feeds and posts are stored here.
- **[goose](https://github.com/pressly/goose)**, to create the database tables (one-time setup):

  ```sh
  go install github.com/pressly/goose/v3/cmd/goose@latest
  ```

## Installation

```sh
go install github.com/pawelwerner/gator@latest
```

This builds a `gator` binary in `$(go env GOPATH)/bin` (usually `~/go/bin`). Make sure that directory is on your `PATH`. This command should print the binary's location:

```sh
command -v gator
```

## Setup

### 1. Create the database

```sh
createdb gator
```

Or, from `psql`:

```sql
CREATE DATABASE gator;
```

### 2. Create the tables

The schema migrations live in this repository under `sql/schema`. Clone the repo and run them with goose:

```sh
git clone https://github.com/pawelwerner/gator.git
cd gator
goose -dir sql/schema postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" up
```

Replace the connection string with your own user, password, host and port.

### 3. Create the config file

`gator` reads its settings from `~/.gatorconfig.json`, which you must create yourself. It needs one key, `db_url`, set to the same connection string you used above:

```json
{
  "db_url": "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable"
}
```

`gator` also stores the logged-in user in this file, under `current_user_name`. The `register` and `login` commands set it for you.

## Usage

```sh
gator <command> [args...]
```

A typical first session:

```sh
# Create a user. This also logs you in.
gator register alice

# Add a feed. You automatically follow feeds you add.
gator addfeed "Boot.dev Blog" https://blog.boot.dev/index.xml
gator addfeed "Hacker News" https://news.ycombinator.com/rss

# In a separate terminal, collect posts every minute. Stop it with Ctrl+C.
gator agg 1m

# Read the 10 newest posts from the feeds you follow.
gator browse 10
```

### Commands

Commands marked with ✓ need a logged-in user.

| Command | Login | Description |
|---|:---:|---|
| `register <name>` | | Create a user and log in as them. |
| `login <name>` | | Switch to an existing user. |
| `users` | | List all users and mark the current one. |
| `addfeed <name> <url>` | ✓ | Add an RSS feed and follow it. |
| `feeds` | | List every feed and the user who added it. |
| `follow <url>` | ✓ | Follow a feed that someone has already added. |
| `following` | ✓ | List the feeds you follow. |
| `unfollow <url>` | ✓ | Stop following a feed. |
| `browse [limit]` | ✓ | Show the newest posts from feeds you follow. Shows 2 if you don't give a limit. |
| `agg <interval>` | | Collect posts continuously, fetching one feed per interval. |
| `reset` | | **Delete all users** and their feeds, follows and posts. Meant for development. |

### Running the aggregator

`agg` runs until you stop it. On each tick it fetches the feed that has gone longest without an update and saves any new posts. Posts that are already saved are skipped. `<interval>` is a Go duration such as `30s`, `5m` or `1h`.

Each tick fetches a single feed, so with *n* feeds each one is refreshed every *n* × `<interval>`. Please don't use a very short interval. It hammers the sites you're reading for little benefit.

## Development

Run from source with `go run .` instead of the installed binary:

```sh
go run . browse 5
```

The database code in `internal/database` is generated by [sqlc](https://sqlc.dev) from the queries in `sql/queries`. Don't edit it by hand. After changing a query, regenerate it:

```sh
sqlc generate
```

To change the schema, add a new numbered migration to `sql/schema` and apply it with `goose ... up`.

| Path | Contents |
|---|---|
| `main.go` | Entry point: loads the config, connects to the database and registers commands. |
| `internal/handlers` | One handler per command, plus the command registry. |
| `internal/middleware` | `LoggedIn`, which loads the current user for commands that need one. |
| `internal/requests` | Fetches and parses RSS feeds. |
| `internal/config` | Reads and writes `~/.gatorconfig.json`. |
| `internal/database` | Generated sqlc code. |
| `sql/schema`, `sql/queries` | goose migrations and sqlc queries. |
